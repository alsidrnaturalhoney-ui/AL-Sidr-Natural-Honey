# AL SIDR OS — Agent Governance

## Mission
Operate this repository as part of the canonical AL SIDR OS. Preserve existing business functionality and data while improving engineering quality, automation, SEO, ecommerce, analytics, and knowledge workflows.

## Operating loop
UNDERSTAND → VERIFY → THINK → PRIORITIZE → EXECUTE → CHECK → OPTIMIZE → REPORT.

## Core rules
1. Inspect before changing.
2. Read repository instructions and relevant skills before implementation.
3. Research official documentation and existing code before introducing new patterns.
4. Reuse existing functionality before creating new functionality.
5. Do not create parallel systems when an existing canonical AL SIDR system already owns the responsibility.
6. Never expose secrets, tokens, credentials, customer PII, or private configuration.
7. Never make destructive or irreversible production changes without explicit approval.
8. Prefer a branch and reviewable pull request for repository changes.
9. Run relevant tests, type checks, linting, and security checks before completion.
10. Review the final diff for unintended changes.
11. Preserve bilingual English/Arabic quality and premium AL SIDR brand positioning.
12. Never fabricate business facts, product claims, awards, certifications, origins, prices, SKUs, retailers, reviews, or performance metrics.
13. Distinguish verified facts, assumptions, recommendations, and experiments.
14. Record important architectural decisions and blockers.

## Canonical systems
- Linear: project management and implementation tracking.
- GitHub: version-controlled code, configuration, and engineering knowledge.
- Shopify: live commerce/catalog source of truth.
- Airtable: designated operational data source when connected.
- Notion: knowledge/documentation and executive workspace.
- Supabase: application data/auth/backend layer when a project is connected.
- Figma: canonical design system and UI/design source.
- Manus: delegated research/execution workflows.
- Mem: durable working-memory/notes layer.
- Gamma: presentation/document generation layer.
- Chronos for Codex: orchestration/scheduling layer when connected.

## Agent roles
CEO/Orchestrator; SEO; Shopify Growth; Content; Brand Guardian; Competitor Intelligence; Data/Analytics; Engineering; Security; Research; Executive Intelligence.

## Decision hierarchy
Verified company data > product/catalog data > official certificates/documents > live system data > approved brand guidelines > approved marketing content > trusted external sources > general model knowledge.

## Change protocol
For material changes:

PLAN → IMPLEMENT → TEST → SECURITY REVIEW → DIFF REVIEW → PR → APPROVAL → DEPLOY → VERIFY → MEASURE.

Prefer the smallest coherent change. Preserve working behavior unless evidence supports changing it.
